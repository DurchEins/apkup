多層防御セキュリティアーキテクチャ

ApkUpは更新ライフサイクルのすべての段階で多層検証を実施します：

apksig v2 / v3

暗号学的APK署名検証

ダウンロードしたAPKや.apkmをPackageInstaller、Shizuku、Root (su) に渡す前に、ApkIntegrityVerifierがv2/v3署名証明書をインストール済みアプリと照合し、不一致やダウングレードを阻止します。

SHA-256 + X.509 TOFU

署名済みF-Droid / IzzyOnDroidインデックスとSHA-256

リポジトリインデックス (entry.jar / index-v1.jar) は固定された64文字SHA-256 X.509証明書フィンガープリントで検証され、ダウンロード済みAPK（SHA256SUMSによる自己更新含む）もSHA-256で検証されます。

Zip-Slip Guard + cacheDir

堅牢化されたアーカイブ展開とストレージ分離

すべてのダウンロードはプライベート内部ストレージ (cacheDir) に保存され、.apkm展開ではZip-Slipと展開爆弾の上限を厳格に適用し、平文HTTPとクラウドバックアップは無効化されています。

Google Tink AES-256-GCM

暗号化された認証情報とホスト分離

ローカル設定と任意トークンはAndroid Keystore上のGoogle Tink (AES-256-GCM) で暗号化されます。Authorizationヘッダーは対象APIホストに固定され、外部リダイレクト時に除去されます。

脆弱性の報告

ApkUpに潜在的なセキュリティ脆弱性（特にAPK署名検証、.apkm展開、Shizuku / Root su実行、認証情報保存、ネットワーク通信）を発見した場合は、公開GitHub IssueやSNSで公開しないでください。

  1. GitHubの機密チャネル Private Vulnerability Reporting をご利用ください。
  2. 問題の詳細、再現手順、影響を受けるバージョン、可能であればPoCをご記載ください。
  3. 報告は迅速に調査し、公開前に修正パッチをリリースします。
