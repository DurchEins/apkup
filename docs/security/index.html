Defense-in-Depth Security Architecture Sicherheitsarchitektur im Überblick

ApkUp enforces multi-layer verification across every update lifecycle stage: ApkUp schützt den gesamten Update-Prozess mehrstufig ab:

apksig v2 / v3

Cryptographic APK Signature Verification Kryptografische APK-Signaturprüfung

Before handing any downloaded APK or .apkm split bundle to PackageInstaller, Shizuku, or Root (su), ApkIntegrityVerifier verifies APK Signature Scheme v2/v3 signing certificates against the currently installed application and blocks certificate mismatches or version downgrades. Vor jeder Übergabe an den Android-PackageInstaller, Shizuku oder Root (su) prüft ApkIntegrityVerifier die APK-Signaturzertifikate (v2/v3 Signing Scheme) gegen die bereits installierte App und blockiert Signaturabweichungen sowie Versions-Downgrades.

SHA-256 + X.509 TOFU

Signed F-Droid / IzzyOnDroid Indexes & SHA-256 Checksums Signierte F-Droid-/IzzyOnDroid-Indizes & SHA-256-Prüfsummen

Repository indexes (entry.jar / index-v1.jar) are verified against pinned 64-hex SHA-256 X.509 signing certificate fingerprints, and downloaded APKs (including ApkUp self-updates via SHA256SUMS) are validated against expected SHA-256 digests. Repository-Indizes (entry.jar / index-v1.jar) werden kryptografisch gegen gepinnte SHA-256-Zertifikats-Fingerprints geprüft; heruntergeladene APKs (einschließlich Selbst-Updates über SHA256SUMS) werden gegen erwartete SHA-256-Prüfsummen validiert.

Zip-Slip Guard + cacheDir

Hardened Archive & Storage Isolation Isolierter Speicher & Archiv-Härtung

All downloads reside in private internal app storage (cacheDir), .apkm split bundles enforce strict Zip-Slip and decompression-bomb limits, and cleartext HTTP traffic as well as cloud backups are strictly disabled. Downloads liegen ausschließlich im privaten internen App-Speicher (cacheDir), .apkm-Bundles sind gegen Zip-Slip und Entpackbomben gehärtet, Klartext-HTTP sowie Cloud-Backups sind deaktiviert.

Google Tink AES-256-GCM

Encrypted Credentials & Host Isolation Verschlüsselte Zugangsdaten & Host-Isolierung

Local preferences and optional tokens are encrypted at rest using Google Tink (AES-256-GCM via Android Keystore). Authorization headers are pinned strictly to their target API hosts and stripped across cross-host redirects. Lokale Einstellungen und optionale API-Tokens werden per Google Tink (AES-256-GCM im Android Keystore) verschlüsselt gespeichert und niemals an fremde Redirect-Domains weitergeleitet.

Reporting a Vulnerability Sicherheitslücken vertraulich melden

If you discover a potential security vulnerability within ApkUp (especially regarding APK signature verification, .apkm archive extraction, Shizuku IPC / optional Root su execution, credential storage, or network transport), please do NOT disclose it via public GitHub issues, discussions, or social media. Solltest du eine Sicherheitslücke in ApkUp entdecken (insbesondere bei der APK-Signaturprüfung, der .apkm-Archiv-Entpackung, der Shizuku- / optionalen Root-(su)-Ausführung, der Token-Speicherung oder dem Netzwerk-Transport), erstelle bitte KEIN öffentliches Issue.

  1. Use GitHub’s confidential Private Vulnerability Reporting. Nutze vertraulich GitHubs Private Vulnerability Reporting.
  2. Detail the issue, steps to reproduce, affected versions, and include a proof-of-concept if available. Beschreibe die Schwachstelle mit Reproduktionsschritten, betroffenen Versionen sowie ggf. einem Proof-of-Concept.
  3. We will review incoming reports promptly, investigate the scope, and release a patch before any public disclosure occurs. Meldungen werden schnellstmöglich geprüft und behoben, bevor Details öffentlich geteilt werden.
