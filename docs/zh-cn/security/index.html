基于 SECURITY.md 的完整安全文档 —— 涵盖受支持版本、密码学校验与负责任的漏洞披露。

纵深防御安全架构

ApkUp 在更新生命周期的每个阶段都执行多层验证：

apksig v2 / v3

密码学 APK 签名校验

在将任何下载的 APK 或 .apkm 分包交给 PackageInstaller、Shizuku 或 Root (su) 之前，ApkIntegrityVerifier 会对照已安装应用校验 v2/v3 签名证书，并拦截证书不匹配或版本降级。

SHA-256 + X.509 TOFU

已签名的 F-Droid / IzzyOnDroid 索引与 SHA-256

仓库索引（entry.jar / index-v1.jar）会对照固定的 64 位 SHA-256 X.509 证书指纹进行校验；下载的 APK（含通过 SHA256SUMS 的自更新）也会进行 SHA-256 验证。

Zip-Slip 防护 + cacheDir

加固归档解压与存储隔离

所有下载均保存在私有内部存储（cacheDir）中，.apkm 解压严格限制 Zip-Slip 与解压炸弹，且明文 HTTP 与云备份已完全禁用。

Google Tink AES-256-GCM

加密凭据与主机隔离

本地设置与可选令牌使用 Android Keystore 上的 Google Tink (AES-256-GCM) 加密存储。Authorization 请求头严格绑定目标主机并在跨域重定向时剥离。

报告安全漏洞

如果您在 ApkUp 中发现潜在安全漏洞（尤其是涉及 APK 签名校验、.apkm 解压、Shizuku IPC / Root su 执行、凭据存储或网络传输），请勿通过公开 GitHub Issue、讨论区或社交媒体披露。

  1. 请使用 GitHub 保密的 Private Vulnerability Reporting 渠道。
  2. 详细说明问题、复现步骤、受影响版本，如有可能请附带验证脚本 (PoC)。
  3. 我们将迅速审核报告、评估影响范围，并在任何公开披露前发布修复补丁。
