Overview & Quick Start Übersicht & Schnellstart

ApkUp is a client-side multi-source Android app updater for Android 10–17 (API 29+). It checks, verifies, and installs updates across 7 ecosystems without telemetry or developer servers. ApkUp ist ein lokaler Multi-Quellen-Updater für Android 10–17 (API 29+). Er findet, verifiziert und installiert App-Updates über 7 Ökosysteme hinweg – komplett ohne Telemetrie oder eigene Server.

Consent First

Zero network calls before source selection Null Netzwerkabfragen vor deiner Quellenwahl

On first launch, ApkUp shows an explicit Choose Update Sources dialog. Only the sources you enable are queried over HTTPS. Beim Erststart zeigt ApkUp den Dialog zur Quellenauswahl. Erst danach werden ausschließlich die von dir aktivierten Quellen per HTTPS abgefragt.

3 Main Tabs

Apps, Updates & Setup Apps, Updates & Setup

Manage installed User/System apps and Watchlist entries in Apps, run single or batch updates in Updates, and configure sources, schedules, and backups in Setup. Verwalte installierte Apps und die Merkliste unter Apps, starte Einzel- oder Sammel-Updates unter Updates und steuere Quellen, Zeitpläne und Backups im Setup.

apksig v2/v3

Cryptographic signature & ABI guard Kryptografischer Signatur- & Architektur-Schutz

Every downloaded APK or .apkm bundle is checked against the installed signing certificate, minSdk, and CPU ABI before installation. Jede heruntergeladene APK oder .apkm-Datei wird vor der Installation gegen das installierte Signaturzertifikat, minSdk und CPU-ABI geprüft.

Läuft ab Android 10.0 (API 29+) in 9 Sprachen (EN, DE, ES, FR, PT, IT, RU, ZH-CN, JA). Funktioniert normal per Dialog oder optional lautlos mit Shizuku / Root (su).

Priority & Pinning

Global priority order with automatic fallback Globale Priorität mit automatischem Fallback

ApkUp evaluates enabled sources according to your drag-and-drop priority list. Pinning an app prioritizes that source first and falls back cleanly if no update is found there. ApkUp prüft aktivierte Quellen in deiner festgelegten Prioritäts-Reihenfolge. Angepinnte Apps bevorzugen ihre feste Quelle und nutzen bei Bedarf automatisch den Fallback.

3-Way Repo Binding

Custom GitHub, GitLab & Codeberg / Forgejo links Eigene GitHub-, GitLab- & Codeberg-/Forgejo-Links

Bind any installed or watched app to owner/repo, multi-level GitLab subgroups (group/sub/project), or self-hosted GitLab/Forgejo instances. Verknüpfe jede installierte oder beobachtete App mit owner/repo, mehrstufigen GitLab-Subgroups (group/sub/project) oder eigenen GitLab-/Forgejo-Servern.

Asset Filtering

ABI matching, FOSS flavor & Regex filters ABI-Erkennung, FOSS-Flavor & Regex-Filter

Automatically selects arm64-v8a / armeabi-v7a / x86_64 assets over universal APKs, prefers FOSS/fdroid flavors when enabled, and supports custom asset Regex filters. Wählt automatisch passende arm64-v8a / armeabi-v7a / x86_64-Pakete vor Universal-APKs, bevorzugt auf Wunsch FOSS-Flavors und unterstützt eigene Regex-Asset-Filter.

Signature Guard

Why Android blocks cross-source certificate changes Warum Android abweichende Signaturen blockiert

Official F-Droid builds are signed by the F-Droid key, while GitHub/Play/IzzyOnDroid builds use the developer key. ApkUp detects mismatches before installation and still lets you Save APK. Offizielle F-Droid-Builds sind mit dem F-Droid-Schlüssel signiert, während GitHub/Play/IzzyOnDroid den Entwicklerschlüssel nutzen. ApkUp warnt vorab – das Speichern der APK bleibt möglich.

Index V2 GitHub Wiki ↗

F-Droid & Index V2 Repositories F-Droid & Index-V2-Repositories

ApkUp features a native F-Droid Index V2 engine with incremental RFC 7396 JSON Merge Patch diffs, cryptographic JAR certificate verification, and 1-tap presets. ApkUp besitzt eine native F-Droid-Index-V2-Engine mit inkrementellen RFC-7396-Diffs, kryptografischer JAR-Zertifikatsprüfung und 1-Tipp-Presets.

RFC 7396 Diffs

Up to 95% less bandwidth on repeat scans Bis zu 95 % weniger Datenverbrauch bei Folge-Scans

Instead of downloading a 50+ MB full index every time, ApkUp verifies entry.jar and applies only the small JSON diff since your last check. Statt jedes Mal einen über 50 MB großen Voll-Index zu laden, prüft ApkUp die kleine entry.jar und wendet nur die Änderungen seit dem letzten Scan an.

X.509 TOFU Pinning

Cryptographic fingerprint verification Kryptografische Fingerprint-Prüfung

Repository JAR signatures are verified against their pinned 64-hex SHA-256 X.509 certificate fingerprint. Any tampered index or diff is rejected immediately. Die JAR-Signaturen jedes Repositories werden gegen den gepinnten 64-stelligen SHA-256-Zertifikats-Fingerprint geprüft. Manipulierte Indizes werden sofort abgewiesen.

API / PAT GitHub Wiki ↗

Configuring GitHub, GitLab & Codeberg Personal Access Tokens Zugangs-Tokens (PAT) für GitHub, GitLab & Codeberg einrichten

Public repositories work out of the box without tokens. Adding a read-only Personal Access Token eliminates API rate limits (60 → 5,000 req/hr on GitHub) and enables batched GraphQL queries. Öffentliche Repositories funktionieren sofort ohne Token. Ein Read-Only-Token hebt jedoch enge API-Limits auf (bei GitHub von 60 auf 5.000 Abfragen/Stunde) und aktiviert gebündelte GraphQL-Checks.

5,000 req/h + GraphQL

GitHub Fine-Grained Token (Read-Only) GitHub Fine-Grained Token (Nur Lesezugriff)

Create a Fine-grained token at github.com/settings/personal-access-tokens with Public Repositories (read-only) — no write scopes needed. ApkUp verifies the token and shows your live remaining quota. Erstelle unter github.com/settings/personal-access-tokens ein Fine-grained Token mit Public Repositories (read-only) – keine Schreibrechte nötig. ApkUp testet das Token direkt beim Speichern.

read_api Scope

GitLab & Codeberg / Forgejo Tokens GitLab- & Codeberg-/Forgejo-Tokens

For GitLab, create a Personal Access Token with the read_api scope. For Codeberg or self-hosted Forgejo, generate a read-only repository token in User Settings → Applications. Erstelle für GitLab ein Token mit dem Scope read_api. Für Codeberg oder eigenes Forgejo genügt ein Read-Only-Token unter Einstellungen → Anwendungen.

AES-256-GCM

Hardware-backed encryption & redirect stripping Hardware-Verschlüsselung & Redirect-Schutz

Tokens are encrypted locally with Google Tink (AES-256-GCM) in Android Keystore. ApkUp’s OkHttp interceptor strictly strips Authorization headers on any cross-host redirect (e.g. to CDN asset servers). Alle Tokens liegen AES-256-GCM-verschlüsselt im Android Keystore. Bei Weiterleitungen auf externe CDN-Server entfernt ApkUp automatisch jeden Authorization-Header.

1-Tap Test

Built-in Token Verification Sheet Integrierte Token-Prüfung mit einem Tipp

Tap Verify Token in Setup → Update Sources → GitHub / GitLab to confirm validity, account handle, and remaining API quota immediately. Tippe im Setup bei GitHub oder GitLab auf Token prüfen, um Gültigkeit, Account-Name und verbleibendes Abfrage-Kontingent sofort zu testen.

Setting up Shizuku (Quick Guide) Shizuku einrichten (Kurzanleitung)

Shizuku is completely optional — standard Android installs work without it. Pairing Shizuku enables zero-touch silent background updates on stock, non-rooted Android 11+ devices. Shizuku ist komplett optional – der normale Android-Installationsweg funktioniert jederzeit ohne Einrichtung. Mit Shizuku laufen Updates auch ohne Root vollautomatisch im Hintergrund.

Wireless Debugging Setup (Android 11+ — No PC or Root Needed) Einrichtung per Kabellosem Debugging (ab Android 11 – ohne PC & ohne Root)

  1. 01

    Install Shizuku & enable Developer Options Shizuku installieren & Entwickleroptionen aktivieren

    Install the official Shizuku app (from Google Play or GitHub) and tap Build Number 7 times in Android Settings → About Phone to unlock Developer Options. Installiere die offizielle Shizuku-App (aus dem Play Store oder von GitHub) und tippe in den Android-Einstellungen 7-mal auf die Build-Nummer.

  2. 02

    Pair Shizuku with Wireless Debugging Shizuku über Kabelloses Debugging koppeln

    Connect to Wi-Fi, tap Pairing in Shizuku, open Developer Options → Wireless Debugging → Pair device with pairing code, and enter the 6-digit code in the Shizuku notification. Verbinde dich mit einem WLAN, tippe in Shizuku auf Koppeln, öffne Entwickleroptionen → Kabelloses Debugging → Gerät mit Kopplungscode koppeln und gib den 6-stelligen Code ein.

  3. 03

    Start Shizuku & authorize ApkUp Shizuku starten & ApkUp berechtigen

    Tap Start in Shizuku, then open ApkUp → Setup → Installation & Automation → toggle Use Shizuku for background installs and tap Allow on the prompt. Tippe in Shizuku auf Starten, öffne danach ApkUp → Setup → Installation & Automatisierung → aktiviere Shizuku für Hintergrundinstallationen nutzen und bestätige die Freigabe.

Alternative: Starting Shizuku via PC (ADB) or Root Alternative: Shizuku per PC (ADB) oder auf Root-Geräten starten

On Android 10 (or if you prefer USB debugging), run "adb shell sh /sdcard/Android/data/moe.shizuku.privileged.api/start.sh" from a PC. On rooted devices, simply choose "Start (for rooted devices)" inside Shizuku — or use ApkUp’s direct Root (su) installer toggle. Unter Android 10 (oder per USB-Debugging am PC) lässt sich Shizuku über "adb shell sh /sdcard/Android/data/moe.shizuku.privileged.api/start.sh" starten. Auf gerooteten Geräten kannst du Shizuku direkt per Root starten – oder in ApkUp einfach den direkten Root-Installer (su) aktivieren.

IPC Pipeline

Elevated PackageInstaller Session via Binder Privilegierte PackageInstaller-Sitzung per Binder

After apksig v2/v3 and ABI checks pass, ApkUp streams the verified APK (or extracted .apkm splits) into an elevated PackageInstaller session via Shizuku Binder IPC or su pm install-create. Nach bestandener Signatur- (apksig v2/v3) und ABI-Prüfung übergibt ApkUp die APK-Dateien (inkl. .apkm-Splits) an eine privilegierte PackageInstaller-Sitzung über Shizuku oder su.

Self-Update Safety

Deferred self-update at the end of a batch Verzögertes Selbst-Update am Ende eines Durchlaufs

When updating multiple apps including ApkUp itself, ApkUp installs all other apps first and schedules its own update last so the running worker is never killed mid-batch. Wenn bei einem Sammel-Update auch ApkUp selbst aktualisiert wird, installiert ApkUp zuerst alle anderen Apps und führt das eigene Update ganz am Ende aus.

Time Windows

Active hours, quiet hours & automatic catch-up Zeitfenster, Ruhezeiten & automatisches Nachholen

Restrict background checks and auto-updates to an active window (e.g. 02:00–06:00 while charging on Wi-Fi). Deferred checks automatically catch up at the next allowed window. Beschränke Hintergrund-Updates auf ein festes Zeitfenster (z. B. 02:00–06:00 Uhr im WLAN beim Laden). Übersprungene Prüfungen werden im nächsten freien Fenster automatisch nachgeholt.

2 GB Rollback Vault

Automatic pre-update backups & 1-tap rollback Automatische Vorab-Sicherung & schneller Rollback

When Rollback Backups are enabled, ApkUp archives the currently installed base + split APKs in private storage (up to 2 GB LRU) before installing the update. Bei aktivierter Rollback-Sicherung speichert ApkUp vor jedem Update die aktuell installierte Basis- und Split-APK privat (bis zu 2 GB) für einen sofortigen Rollback im Update-Verlauf.

How in-place Root rollback (-r -d) vs. guided non-Root rollback works Unterschied zwischen direktem Root-Rollback (-r -d) und geführtem Rollback ohne Root

Android normally blocks version downgrades unless the app is uninstalled first. With Root (su), ApkUp can execute an in-place downgrade (pm install -r -d) keeping your app data intact where supported by the app. Without Root, ApkUp guides you through a clean two-step flow: uninstalling the newer build and immediately reinstalling the backed-up previous APK (or exporting it to Downloads). Standard-Android blockiert Versions-Downgrades ohne vorherige Deinstallation. Mit Root (su) führt ApkUp ein direktes In-Place-Downgrade (pm install -r -d) unter Erhalt der App-Daten durch. Ohne Root führt dich ApkUp sicher in zwei Schritten durch Deinstallation und sofortige Neuinstallation der gesicherten Vorgänger-APK (oder exportiert sie in deinen Download-Ordner).
